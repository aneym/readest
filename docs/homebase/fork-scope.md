# Household Readest fork scope

The household Android build sets `NEXT_PUBLIC_HOUSEHOLD_BUILD=1` in `scripts/household-build.sh`. This is a thin, offline-first fork of Readest, not a replacement for its local reader. Keep upstream fixes flowing; do not make a network login a prerequisite for opening a local book. The upstream pin is `558ed2af` (`fix(koplugin): pull reading stats in bounded pages (#5833)`). To inspect the whole fork against that pin, use `git diff 558ed2af..HEAD -- apps/readest-app scripts/household-build.sh`; to inspect this polish series alone, use `git log --stat 4223fcbd..HEAD` and `git diff 4223fcbd..HEAD -- apps/readest-app scripts/household-build.sh`. Review local uncommitted changes separately with `git diff` since neither comparison includes them.

## Launcher open contract

`palma-readest://open?calibreId=132&hash=<32-hex-md5>&mode=read` is the BOOX launcher VIEW link. `calibreId` is required, positive and a safe integer. `hash` is optional but, if present, must be 32 hex characters; it is normalized to lowercase. `mode` is `read` (the default) or `listen`. Invalid inputs are ignored. `4801241e` touches `apps/readest-app/src-tauri/gen/android/app/src/main/AndroidManifest.xml`, `apps/readest-app/src-tauri/tauri.conf.json`, `apps/readest-app/src/utils/deeplink.ts`, `src/hooks/useOpenBookLink.ts`, `src/types/book.ts`, `src/utils/transform.ts`, plus the link test.

After local library hydration, resolution tries the exact live book hash first, then the matching `calibreId`, preferring EPUB and then the newest `updatedAt`; deleted books are excluded. A link to the book already displayed in the reader focuses it in place rather than recreating the view. `mode=listen` also requests TTS for a displayed book, or arranges TTS autoplay when opening a document; a streaming audiobook opens its player instead. A valid link whose book is not on this device sends the user to the library with a warning, not to login or a network-only spinner. Cold-start URLs are consumed once; live launcher taps remain actionable.

## Launcher sync-status contract

`c037ac54` touches `apps/readest-app/src-tauri/gen/android/app/src/main/AndroidManifest.xml`, `apps/readest-app/src-tauri/gen/android/app/src/main/java/com/bilingify/readest/HouseholdSyncStatus.kt`, `HouseholdSyncStatusProvider.kt`, `MainActivity.kt`, `src/hooks/useHouseholdStatusExport.ts`, `src/components/Providers.tsx`, and native/hook tests. The exported, read-only ContentProvider authority is `com.bilingify.readest.household`, URI `content://com.bilingify.readest.household/sync-status`. Queries return one row with `pending` (nonnegative count), `last_sync_at` (epoch milliseconds, zero when unknown), `state` (`idle`, `syncing`, `offline`, `error`, or `unpaired`), and `updated_at` (epoch milliseconds). It requires `com.aneym.household.permission.READ_SYNC_STATUS`, declared with Android `normal` protection level; writes are unsupported. Consumers can register a ContentObserver on the URI: native writes call `ContentResolver.notifyChange`, and returned cursors set their notification URI. This is aggregate status, not book contents or a login credential.

## Discover contract (working-tree client)

The Discover client currently lives in uncommitted `apps/readest-app/src/services/discover/` and `src/app/discover/`; there is **no commit SHA in `4223fcbd..HEAD` for these paths yet**. Do not treat it as already shipped. It uses the configured Homebase origin with `/api/books/discover` endpoints: `GET /browse`, `/providers`, `/search?q=&kind=`, `/work?key=` (or `?title=&author=`), `/jobs?active=1`; `POST /requests`, `/jobs/{jobId}/retry`, `/jobs/{jobId}/cancel`. Native POSTs carry `Origin: https://studio.tailf266ac.ts.net`, `X-Homebase-Media-Action: 1` and JSON content type; browsers supply their own Origin. No key or token is embedded in that header.

Offline requests persist under `household.discover.queue` and replay oldest first with stable `requestId` for idempotency. Rejections are retained under `household.discover.rejected` for a visible explanation, rather than retried forever. Last-known browse and work results use `household.discover.browse` and `household.discover.works`. Storage failures are guarded, but if localStorage is denied or full the outbox is not durable; verify on-device before promising offline requests will survive an app kill.
